# Regras do projeto (para o Claude)

- **Idioma:** sempre pt-BR — respostas, código, comentários, mensagens de commit e PR, textos da tela.
- **Somente leitura no banco:** o aplicativo nunca escreve no Firebird do Small Commerce. Só `SELECT`/`WITH`, sempre pela conexão blindada de `src/firebird.js` (trava de comando + transação `readOnly`, READ COMMITTED + REC_VERSION, sem espera). Nada de `UPDATE`/`INSERT`/`DELETE`, índices, DDL ou colocar o banco em modo somente leitura — a trava vale só para as conexões deste aplicativo, nunca para o PDV.
- **Banco pela rede primeiro:** a descoberta (`src/localizar-banco.js`) procura o servidor da rede antes do Firebird desta máquina (`127.0.0.1` é a última opção) e só aceita arquivos chamados `SMALL.FDB`. Nunca abrir `.FDB` por compartilhamento/unidade de rede (só ler `.ini`/`.cfg` por lá).
- **Modos:** "cópia" é o padrão (como o Relatórios FDB-FBK); "leitura direta" é opcional (como o Relatórios SSH). Mudança num modo não pode quebrar o outro.
- **Leitor de código de barras (USB/Bluetooth, modo teclado):** o campo de busca fica sempre em foco, o texto é selecionado depois de cada leitura e o produto lido abre no cartão de preço. Não existe leitor por câmera neste projeto.
- **PCs antigos e novos:** o código precisa rodar no Electron 44 (Windows 10/11 x64) **e** no Electron 22.3.27 (Windows 7/8/8.1 e 32 bits): Node 16 no processo principal e Chromium 108 na tela. Proibido: `structuredClone`, `Array.prototype.findLast`, `fetch` no processo principal, CSS aninhado, `color-mix`, `:has()`. Testar a tela nos dois quando mudar `ui/`.
- **Código à prova de erros:** antes de entregar, procurar bugs e cenários de erro no próprio diff (rede caindo, servidor desligado, pasta de rede lenta, banco sem a tabela, senha errada, config estragado, Windows 7, 32 bits, sem Firebird local) e corrigir. Toda leitura de rede tem prazo; nada pode congelar a janela.
- **Changelog:** o cabeçalho de cada arquivo traz só a entrada da versão atual (mais a linha "Histórico completo das versões: CHANGELOG.md no repositório."). O histórico completo fica no `CHANGELOG.md`: nova entrada no topo da seção do arquivo e tabela de versões atualizada. Toda mudança de código sobe a versão do arquivo; mudança percebida pelo usuário sobe também a `version` do `package.json` (versão do aplicativo).
- **README sempre atualizado:** toda mudança que o usuário perceba (recurso, tela, opção, chave do config, arquivo, dependência, versão, quantidade de testes) atualiza o `README.md` no mesmo PR — badges, "Tecnologias e bibliotecas", "Uso no dia a dia", configuração e solução de problemas. Escrito para quem não é técnico.
- **Exemplos neutros:** placeholders, testes e documentação sem nomes de pessoas, clientes, lojas ou marcas (ex.: "RAÇÃO GATO 1KG", "FORNECEDOR A", "SERVIDOR").
- **Arquivos do Windows:** `.bat` em ASCII com CRLF.
- **Antes de entregar:** `npm test` verde; validar a tela com Playwright + Electron em modo `--demo` (Electron 44 e 22) quando `ui/`, `main.js` ou `preload.js` mudarem; gerar os instaladores (`electron-builder`) quando a configuração do build mudar.
- **Pull requests:** depois de abrir o PR e com os testes verdes, **fazer o merge automaticamente** (pedido do dono do repositório) — não esperar aprovação manual.
- **Créditos:** autor Ruda Gabriel (`@author Ruda Gabriel` nos cabeçalhos; rodapé do README).
